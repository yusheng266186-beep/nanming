## 字段与证据规则

- 工作簿通过 workbook.xml 与 relationships 解析真实工作表，不再固定读取 sheet1.xml；列由表头名称定位。
- 每个字段保留工作簿SHA、工作表、行号、单元格地址、原值、单元格类型、数字格式和公式。存在合并区域时只读取明确锚点，绝不因空单元格就跨组向前填充。
- 院校代码、专业组代码、专业代码按文本保存；数值代码只在明确的纯零数字格式下恢复显示前导零。0和缺失分开。
- 计划人数为非负整数；费用与学制只接受可明确解析的数值，带单位或说明文字保留原文并标记未知。币种和计费周期仍需核实。
- 不执行公式，公式缓存不进入数值事实；Excel错误值不变成0。
- 26计划列对应2026，25/24/23历史列分别对应2025/2024/2023。文件名中的“22—25”不证明有2022列。
- 组最低、专业最低/平均/最高分分别存储，组最低仅作工作簿表头语义解释，未核实为官方口径；没有创建group_filing_min。
- 历史记录的类别、批次、分数口径和跨年主体身份保持未知，不能从2026计划行倒推；没有建立跨年可比关系。
- 排名0判无效；缺失专业历史不复制组线。当前两张配置工作表没有一分一段表，该输入仍需单独补充。

## 可重跑命令

在 `nanhang-app` 目录执行，工作簿默认从工程父目录读取，因此目录更名不影响运行：

```powershell
py -3.12 pipelines/task03/extract_workbook_samples.py
py -3.12 -m unittest discover -s pipelines/task03 -p test_workbook_intake.py
py -3.12 pipelines/task03/validate_workbook_samples.py
npm run validate
```

提取器只读源Excel，写入单独开发JSON。独立校验脚本重新解析原工作表与原单元格，核对文件SHA、原始编码值、文本解码值和公式，不以“代码能运行”代替证据一致性。`npm run validate` 的样本测试不依赖根目录Excel，单独源码包也可运行；重跑提取及原单元格复核需要两份原工作簿。

学费原值不直接进入预算判断：`tuition_currency` 与 `tuition_period` 均为空，`tuition_comparable=false`。确认币种、计费周期和备注前，不默认人民币或每年收费；包括可能以港币标示的院校。
