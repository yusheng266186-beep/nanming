# 聊天模型接入：百度千帆（Token Plan 个人版）

本轮把南溟的 AI 对话接到真实模型上，配置项与北辰保持一致，两套系统可以共用同一份凭据说明。
**密钥只在环境变量里**：不进仓库、不回显、不进错误消息；这一点有测试盯着。

## 一、环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `QIANFAN_API_KEY` | 是 | 千帆的 API Key，只放在运行环境（本机 shell 或云函数配置） |
| `QIANFAN_MODEL` | 是 | 模型名，必须与 Token Plan 里可用的模型一致（如 `glm-5.2`） |
| `QIANFAN_BASE_URL` | 否 | 默认 `https://qianfan.baidubce.com/v2/tokenplan/personal`；只允许官方域名与标准 Token Plan 路径 |
| `NANHANG_AI_THINKING_TIER` | 否 | 服务端默认档：`deep`（默认，开思考）/ `standard`（不下发该字段）/ `speed`（关思考）。学生可以在界面上自己切，学生选了就以学生为准 |
| `QIANFAN_THINKING` | 否 | `enabled` / `disabled`；单独设置会覆盖档位 |
| `QIANFAN_THINKING_BUDGET` | 否 | 与 `QIANFAN_THINKING=enabled` 搭配使用的思考预算（≥100 才生效） |
| `QIANFAN_MAX_TOKENS` | 否 | 单轮上限，默认 2000（≥200 才生效）。**思考与正文共用这份预算**，开思考要一起调大 |
| `NANHANG_AI_UPSTREAM` | 否 | `qianfan` 或 `fake`；不设置时按下面的规则自动判断 |
| `NANHANG_AI_FIRST_BYTE_TIMEOUT_MS` | 否 | 首字节超时，默认 30000；开启思考档位后应放宽 |
| `NANHANG_AI_TOTAL_TIMEOUT_MS` | 否 | 整轮超时，默认 90000；开启思考档位后应放宽 |
| `NANHANG_API_PORT` | 否 | 本地服务端口，默认 8790 |
| `NANHANG_FAKE_SCENARIO` | 否 | 用假上游演练失败路径（timeout、unsafe-output 等），不花钱 |

**缺 `QIANFAN_API_KEY` 或 `QIANFAN_MODEL` 任何一个，就当作「未配置千帆」**，与北辰同一套判断：
不会拿着半个配置去发请求。上游选择规则只有三条：

1. `NANHANG_AI_UPSTREAM=qianfan` → 必须用真模型；配置不全会**拒绝启动**，绝不悄悄退回假上游；
2. `=fake`，或设了 `NANHANG_FAKE_SCENARIO` → 用本地假上游（验收失败路径用）；
3. 不设置 → 千帆两项齐全就自动用真模型，否则用假上游。

启动日志与 `/readyz` 的 `upstream` 字段会写明当前用的是 `qianfan` 还是 `fake-local`，不会静默切换。

## 二、本地跑一轮

```bash
cd nanhang-app

# 1) 起 AI 服务（把密钥放进当前 shell，不要写进任何文件）
QIANFAN_API_KEY=你的Key QIANFAN_MODEL=glm-5.2 npm run api:start
# 看到 "upstream":"qianfan" 才算接上了

# 2) 另开一个窗口起前端（桌面上的「南溟-主前端.cmd」也可以）
npm run web:dev
```

前端默认连 `http://127.0.0.1:8790`，可用 `VITE_NANHANG_API_BASE` 覆盖。AI 面板需要访问码，
开发档的访问码是 `local-trial-code`（`apps/api/src/demo-context.ts`，仅本地演示；正式签发属于 TASK-13）。

## 三、云端函数的对应关系

云函数（SCF）部署时，环境变量与本地**同名同义**，直接照搬上表即可；北辰那套运维习惯也一并适用：
密钥只进函数配置、更新函数避开学生在线时段、留回滚包。两处**必须改**的地方：

1. **CORS**：本地服务只放行 localhost 来源（`apps/api/src/server.ts` 的 `ALLOWED_ORIGINS`）。
   页面在 Pages、函数在云上时，要把 Pages 的来源加进白名单，否则浏览器会拦掉请求。
2. **监听地址**：本地只监听 `127.0.0.1`；云函数/容器要监听注入的端口与 `0.0.0.0`。

## 三·五、思考档位：服务端默认最高档，学生可以自己切

北辰把档位固定在云端最高档、页面不带模型字段。南溟沿用「服务端配置」这一点，但**默认档是
`deep`（质量优先，负责人的明确选择）**，同时在界面上给学生一个三选一的开关
（谈心章节 AI 面板的「回答方式」）。学生切档只影响下一轮，已经拿到的回复不作废。

| 档位 | 下发内容 | 界面上叫什么 | 实测（同一句话） |
|---|---|---|---|
| `deep`（默认） | `thinking: enabled` + 预算 4096，上限 8000 | 深（默认） | 17.0 秒 / 9.5 秒 |
| `standard` | 不下发该字段，由端点决定 | 标准 | 24.8 秒 / 19.8 秒（端点默认就是这个档） |
| `speed` | `thinking: disabled`，上限 2000 | 快 | 4.9 秒 |

实测结论：

- **深档确实更慢，慢在出字之前**（模型要想完才开始说），所以等待提示必须一直在；
  服务端在深档下把首字节上限放宽到 120 秒、整轮 300 秒，否则每一轮都会在默认的 30 秒被掐断。
- **思考与正文共用单轮 token 上限**：`max_tokens=300` 且开思考时，300 个 token 全用在思考上、
  正文 0 字。深档因此配 8000 的上限——改档位时不要只改思考预算、忘了上限。
- 三档都实测跑通，格式（正文 + 标记 + JSON）与安全校验在每一档下都成立。

## 三·六、提示词：借北辰的谈话纪律，问南溟自己的问题

北辰的提示词在前端页面里（它的中转函数是纯转发）。我们借的是它的**谈话纪律**，
提问内容则按南溟自己的产品重写——北辰问的是「选文还是选理」，南溟要分辨的是三条专业方向。

**借来的纪律（不照抄内容）**

- 每轮先接住学生刚说的**具体内容**，再往前走一小步；不要「我非常理解你的感受」这类套话，不评判不说教。
- **只问一个问题**，而且问题要能引出一段经历、一个感觉或一次取舍，不是收集抽象性格词。
- **分开记录**：喜欢／擅长／家长期待／担心竞争各自独立，冲突如实保留；只有至少两类线索相互印证才说
  「更偏向」，否则写「仍在观察」。
- **快捷回答只是线索不是结论**；只点选项没有细节时，不当成强证据。
- **反测评腔**：正文与建议理由都不许出现证据编号、「第几问」「判断依据」「证据表明」。
- 对话变长时换切入角度（回到最近一次具体经历、一个还没展开的日常侧面、一句他反复说的话），
  不在原地换词重问。

**按南溟重写的提问内容**

- 明确告诉模型：要分辨的方向只有三个——数据整理与信息核对、结构制作与修改、规则阅读与流程记录，
  提问要能帮学生看出哪条更像他，而不是泛泛聊兴趣。
- 把每条方向**真实配套的那件小任务**写进提示词（整理公开小表格标空值／用纸搭桥记录测试方法／
  读公开规则写出流程），并指示模型聊到某条方向时问学生愿不愿意试、试完什么感觉——
  这是本项目里最有说服力的验证方式，比再问十个问题都管用。
- 要求**问现实条件**（家里怎么想、费用与地域的硬限制、必须照顾的安排），因为它们会进入航线图的现实条件。
- 要求学生已存的原话要先用起来，不重复问已经答过的事。
- 明确划走不属于 AI 的话题：分数、位次、能不能上某所学校由数据库与匹配规则回答；学生问到时把人引到
  「分数轴」和「航线图」，**也不许主动把话题引到具体学校或专业上**（实测中模型这么做过一次，因此写进提示词）。

**实测复验（默认深档）**

- 含糊回答「我也不知道自己喜欢什么，成绩都一般」→ 只问一个问题，且问的是一次具体经历；
  给出 1 条**待确认**方向的建议，行动是「挑一份你熟悉的小数据做一次整理，顺手记下哪一步你最不觉得累」。
- 回答里提到家里希望留在四川、学费有压力 → **0 条建议、0 条行动**：没有硬凑方向，只是接住并继续问。

**没有搬的，以及原因**

- **思考低语**（把模型真实思考的最后一句淡入给学生看）：南溟的规则是思考内容属于草稿、绝不发给学生，
  而且它不过安全扫描——万一模型在思考里写「可以考虑冲一冲」，那句话就到了学生眼前。
  等待体验改用打字指示器解决，不用泄露思考。
- **知识库里的具体数字**（覆盖率 96%、招生计划 28.7 万等）：南溟不许模型自行断言数据，
  事实只能来自发布包。这些数字一旦写进提示词，模型就会当事实说出来。
- **领航／夜航双模式与可点选项**：南溟的问一问面板本来就是自由输入，等同夜航模式；
  引入选项等于新增一套交互与判分口径，不是本轮该做的事。

## 三·七、两种聊法：引航 / 泛舟

参考北辰的领航／夜航（一种给现成答案、一种完全自由），名字按南溟自己的主题起：

- **引航**（默认）——引航员上船带路，每一步都摆出现成答案，点一下就算你答了；
- **泛舟**——取自「泛若不系之舟」（《庄子》，与「南溟」出自同一篇），不设路线、随水而行。

学生在谈心章节的 AI 面板里随时切换，做成两张可以挑的卡（选中那张金铜边框、米色底、衬线名字），
而不是一个小开关：**这是学生自己的选择**。切换下一轮生效，已聊过的内容不受影响。

| | 引航（默认） | 泛舟 |
|---|---|---|
| 问法 | 每轮给 3~4 个可以直接点的答案 | 只问问题，不给选项 |
| 学生怎么答 | 点一个答案，或自己写 | 全部自己写 |
| 服务端 | 提示词要求填 `options`，JSON 里必须给 | 提示词要求 `options` 必须为空数组 |

**它怎么走通的（已实测渲染）**：模式随每一轮请求发给服务端（请求体新增 `mode`，只接受 `guided` / `open`），
提示词按模式要求输出，输出契约里的 `options` 与建议、行动一样要过安全校验
（最多 4 个、每个不超过 24 字、不许出现链接／HTML／录取概率）。

**两道防线保证自由探索不会冒出按钮**：上游在非 `guided` 模式下把 `options` 清空；
前端也只在 `ai.mode === "guided"` 时才渲染选项——两条都有测试盯着。
切走模式会清掉上一轮的选项（它属于上一轮的问法），但已经拿到的回复保留，学生不会丢信息。

**真模型复验（默认深档）**：

- 选择作答：「我不知道自己喜欢什么」→ 返回 4 个可点答案，都是具体的经历或态度
  （「拆装过小物件或做过点手工」「看说明或研究规则时挺专注」「喜欢把乱糟糟的东西排个序」
  「好像真没有，平时都在刷手机」——最后一个就是允许出现的那个「还没想过」）。
- 把第一个答案当作学生的回话再发一轮 → 模型接着问了动手的细节，并**主动给出南溟配套的那件小任务**
  （用纸搭一座小桥、记录怎么测试结实程度），这正是提示词里「每条方向配一件小任务」那一节的落地。
- 自由探索：同样一句话，**0 个选项**。

**等待时间要有心理准备**：默认深档下实测 25~50 秒一轮（深档本来就慢，选择作答还要多想几个答案）。
面板目前只有「等待回复…」，如果试用反馈说等得难受，优先做的是等待提示（北辰那套带秒数与阶段文案的做法），
而不是把默认档调低。

## 四、与北辰的差异（都不是疏漏）

| | 北辰 | 南溟 |
|---|---|---|
| 输出 | 两段式文本，前端按标记分块渲染 | 正文 + 结构化 JSON；**结构化段不下发**，由网关校验后才作为建议卡片 |
| 思考档位 | 固定 `enabled` + `reasoning_effort: max`（云端写死，学生不能改） | 服务端默认 `deep`（最高档），**学生可在界面上自己切三档** |
| 提示词位置 | 前端页面里 | 服务端（`packages/ai-gateway`），前端无法篡改；纪律借鉴自北辰 |
| 超时 | 9 分钟 | 30 秒首字节 / 90 秒整轮，可用环境变量放宽 |
| 鉴权 | TOTP + 会话 | 沿用网关既有会话机制；学生身份是 TASK-13，尚未做 |

南溟的回复要过 `validateCareerTurnOutput`：正文不能出现概率、冲稳保、链接或 HTML；每条方向建议
必须引用**学生自己保存过的原话 ID**，编造的证据 ID 会被拦下并把整条建议降级。所以模型侧提示词里
同时给了「边界七条 + 输出格式 + 可引用证据 + 可选方向 ID」。

## 五、故障对照

| 现象 | 原因与处置 |
|---|---|
| 启动即退出，提示需要 `QIANFAN_API_KEY` | 显式要求了 `qianfan` 但配置不全；补全或去掉 `NANHANG_AI_UPSTREAM` |
| 启动即退出，提示主机不在允许名单 | `QIANFAN_BASE_URL` 被改成了非官方域名；这是防止密钥外发的保护 |
| 回复被替换成「未通过安全校验」 | 模型输出了概率、冲稳保、链接或 HTML；看 `error` 帧的 detail，按提示词收紧 |
| 每轮都没有方向建议 | 该会话没有已保存的原话，或模型给的建议没引用注册过的证据 ID |
| 首字节很慢甚至超时 | 端点默认开着思考档位；先试 `QIANFAN_THINKING=disabled`，或放宽两个超时变量 |
| 正文几乎为空、但确实烧了 token | 思考吃满了单轮上限。实测：`thinking` 开启 + `max_tokens=300` 时，300 个 token 全用在思考上、正文 0 字。把 `QIANFAN_MAX_TOKENS` 调大（4000 起），或设 `QIANFAN_THINKING=disabled` |
| 上游 401/403 | 密钥或模型名与 Token Plan 不匹配；错误消息里只有状态码，不含密钥 |

## 六、本轮没有验证的部分（如实标注）

- **已于 2026-09-12 用真实凭据验证通过。** 凭据按交接库自己的规矩从《操作执行清单》附录 A 读取，
  探针脚本放临时目录、用完即删，全程没有打印密钥。结果：
  - 直连探针 HTTP 200，首字节约 1.0 秒，端点与模型名（`qianfan-code-latest`）有效；
  - 完整网关跑一轮：HTTP 200、约 16 秒、143 个 delta 帧、**0 个 error 帧**，552 字正文，
    **未被安全校验降级**；1 条建议同时引用了注册过的两条原话，2 条行动，
    「学生看到的文字」与「校验后的 reply」**逐字相同**；
  - 模型确实在守边界：它主动把「兴趣表达」与「实际经历」分开陈述（`PROMPT_BOUNDARY` 第 2 条）。
- 仍然未验证：多轮连续对话、多人并发、真实学生规模下的限额与计费，
  以及上游不遵守「正文 + 标记 + JSON」格式时的兜底在真实模型上的表现（当前靠提示词约束）。
- **本地 API 仍是演示宿主，这一条给学生用之前必须补**：服务端的证据注册表是
  `demoEvidence()` 里的合成原话，而前端目前发送 `context: []`、不带学生自己的回答。
  于是真实模型会引用**学生没有写过的演示原话**来生成建议卡片，卡片上却写着「来自学生自己保存的
  原话」。自己或老师做技术验证没问题，**但绝不能这样给学生用**。正确的修法是让前端把学生自己
  的回答（原话与证据 ID）随请求发给服务端，由服务端用它替换演示注册表；这属于请求契约的改动
  （`ALLOWED_TURN_FIELDS`，即「客户端被允许发送哪些字段」），要单独做、单独测。
- 云函数宿主、生产 CORS、学生身份（TASK-13）三项未动。
- 模型是否严格遵守「正文 + 标记 + JSON」的格式只在提示词层面约束；不遵守时会走兜底
  （末尾 JSON 识别、无建议保留正文），不会把原始 JSON 显示给学生，但建议卡片会为空。
