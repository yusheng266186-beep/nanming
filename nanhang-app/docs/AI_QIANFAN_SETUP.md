## 一、环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `QIANFAN_API_KEY` | 是 | 千帆的 API Key，只放在运行环境（本机 shell 或云函数配置） |
| `QIANFAN_MODEL` | 是 | 模型名，必须与 Token Plan 里可用的模型一致（如 `glm-5.2`） |
| `QIANFAN_BASE_URL` | 否 | 默认 `https://qianfan.baidubce.com/v2/tokenplan/personal`；只允许官方域名与标准 Token Plan 路径 |
| `NANHANG_AI_THINKING_TIER` | 否 | 服务端默认档：`deep`（默认，开思考）/ `standard`（不下发该字段）/ `speed`（关思考）。学生可以在界面上自己切，学生选了就以学生为准 |
| `QIANFAN_THINKING` | 否 | `enabled` / `disabled`；单独设置会覆盖档位 |
| `QIANFAN_THINKING_BUDGET` | 否 | 与 `QIANFAN_THINKING=enabled` 搭配使用的思考预算（≥100 才生效） |
| `QIANFAN_MAX_TOKENS` | 否 | 单轮上限，默认 2000（≥200 才生效）。**思考与正文共用这份预算**，开思考要一起调大 |
| `NANHANG_AI_UPSTREAM` | 否 | `qianfan` 或 `fake`；不设置时按下面的规则自动判断 |
| `NANHANG_AI_FIRST_BYTE_TIMEOUT_MS` | 否 | 首字节超时；检测到开启思考时默认 120000，否则默认 30000；显式值优先 |
| `NANHANG_AI_TOTAL_TIMEOUT_MS` | 否 | 整轮超时；检测到开启思考时默认 300000，否则默认 90000；显式值优先 |
| `NANHANG_API_PORT` | 否 | 本地服务端口，默认 8790 |
| `NANHANG_FAKE_SCENARIO` | 否 | 用假上游演练失败路径（timeout、unsafe-output 等），不花钱 |
| `NANHANG_REDIS_HOST` / `_PORT` / `_PASSWORD` | 否* | 共享会话存储；**三项齐全才算配好**。配了走共享档，缺一项退回单实例内存档（2026-09-14 起线上就是这个状态：实例已销毁、三项已移除） |
| `NANHANG_AI_ALLOW_MEMORY_STORE` | 否 | 没有共享存储时跑单实例内存档的开关：`1` 才允许。生产档下没有它、又缺共享存储时**整个函数不会启动**（不只是 AI 关闭）。当前线上为 `1` |
| `NANHANG_ALLOW_DEMO_EVIDENCE` | 否 | 演示原话是否可顶替学生原话；默认只在假上游下允许，接真模型时禁止 |
| `NANHANG_TOTP_SECRET` | 线上必填 | AI 谈心入口的 Base32 原始种子；RFC 6238、SHA-1、30 秒、6 位。只放云函数环境或本机 `private/`，不得进仓库 |

**缺 `QIANFAN_API_KEY` 或 `QIANFAN_MODEL` 任何一个，就当作「未配置千帆」**，与北辰同一套判断：
不会拿着半个配置去发请求。上游选择规则只有三条：

1. `NANHANG_AI_UPSTREAM=qianfan` → 必须用真模型；配置不全会**拒绝启动**，绝不悄悄退回假上游；
2. `=fake`，或设了 `NANHANG_FAKE_SCENARIO` → 用本地假上游（验收失败路径用）；
3. 不设置 → 千帆两项齐全就自动用真模型，否则用假上游。

启动日志与 `/readyz` 的 `upstream` 字段会写明当前用的是 `qianfan` 还是 `fake-local`，不会静默切换。

### 正式环境 TOTP（API 版本 9）

正式环境不再读取 `NANHANG_TRIAL_ACCESS_CODE`。学生输入由认证器根据 `NANHANG_TOTP_SECRET` 实时生成的 6 位码；服务端允许前后一个 30 秒窗口用于轻微时钟偏差，并在 Redis 中用 `SET NX EX` 原子消费凭据。同一码成功兑换一次后，再次提交返回 `TOTP_REPLAYED`。这与北辰当前星门规则一致，也意味着课堂发放需要逐人、逐窗口进行；不能把同一个 6 位码同时发给多名学生。

维护者录入认证器时使用：账户 `Nanming`，签发者 `Nanming`，算法 SHA-1，位数 6，周期 30 秒。原始种子在本机 `private/nanming-totp-secret.txt` 和 SCF 环境变量中各保留一份；验证日志只记录种子 SHA-256 指纹，不记录原值。

## 三、云端函数的对应关系

云函数（SCF）部署时，环境变量与本地**同名同义**，直接照搬上表即可；北辰那套运维习惯也一并适用：
密钥只进函数配置、更新函数避开学生在线时段、留回滚包。两处**必须改**的地方：

1. **CORS**：本地服务只放行 localhost 来源（`apps/api/src/server.ts` 的 `ALLOWED_ORIGINS`）。
   页面在 Pages、函数在云上时，要把 Pages 的来源加进白名单，否则浏览器会拦掉请求。
2. **监听地址**：本地只监听 `127.0.0.1`；云函数/容器要监听注入的端口与 `0.0.0.0`。

### 公网访问路径 = 一条 http 触发器（2026-09-12 实测）

控制台函数页上那行「访问路径」不是函数自带属性：它是函数的一条 `http` 触发器（函数 URL）。
用 `CreateFunction` API 建出来的 Web 函数**不会自动带触发器**，`GetFunction` 返回的 `AccessInfo.Host`
也是空字符串，所以「没有访问路径」不是没开通，而是触发器不存在。补法是建触发器，
建完 `ListTriggers` 的 `TriggerDesc.NetConfig.ExtranetUrl` 就是访问路径：

```python
req = models.CreateTriggerRequest()
req.FunctionName = "nanming-api"
req.TriggerName  = "<10 位小写字母数字>"        # 触发器名，平台另生成 URL 里的随机段
req.Type         = "http"
req.Qualifier    = "$LATEST"                     # 跟随最新代码，改完代码不必再打版本
req.Enable       = "OPEN"
req.TriggerDesc  = json.dumps({
    "AuthType": "NONE",
    "NetConfig": {"EnableIntranet": False, "EnableExtranet": True},
    "CorsConfig": {"Enable": False},             # CORS 由服务端自己发，别让平台再叠一层
    "ApiGwCompatible": True, "EnableSimpleMode": False,
})
```

`NANHANG_CORS_ORIGINS` 与前端 `VITE_NANHANG_API_BASE` 都要跟着这个域名走。

更新函数代码时不必在本机留一份密钥：先用 `GetFunction` 把线上函数现有的 `Environment.Variables`
读回环境变量，再跑 `scripts/deploy_function.py`——密钥全程只在内存里，
本机因此没有 `.env`，也没有任何密钥文件（2026-09-12 更新到版本 3 就是这么做的）。

所以 2026-09-14 直接销毁了 `crs-bdr4f2z6`，并从函数环境移除 `NANHANG_REDIS_*` 三项。

**恢复不用手敲命令**：打开服务开关网页（任意设备，手机也行）
`https://nanming-100051087352-1459223409.cos.ap-chengdu.myqcloud.com/switch/b76b5b97.html`，点「开启 Redis」——
云端中转会创建实例、必要时开通外网地址、探测 `AUTH+PING`、把三项变量写回函数并把内存档开关改回 0。

**前置条件：账户不能欠费**（欠费时腾讯云直接拒绝创建按量资源，实测 `ERR_INSUFFICIENT_BALANCE`）。
下面的表格与取舍是 2026-09-12 建实例时的记录，手动重建时照它做。冻结与恢复清单另见
[冻结记录](verification/cloud-cost-freeze-2026-09-14.json)。

| 项 | 值 |
|---|---|
| 实例 | `crs-bdr4f2z6`（`nanming-state`），成都一区，Redis 7.0 标准架构 **256MB**、1 副本（已销毁） |
| 计费 | 按量计费，约 **¥0.0368/小时**（≈¥0.9/天，一直开着约 ¥26.5/月）；用完在控制台销毁即可 |
| 为什么是 256MB | 用量只有几十 MB 以下的会话键（实测 `SizeUsed` 为 0），1GB 是当初按「MemSize 必须是 1024 整数倍」误判选的；实测 256MB 可以买，已用 `UpgradeInstance` 原地缩容，地址端口不变。降配规则：缩容后规格须 ≥ 已用容量的 1.3 倍 |
| 网络 | 与函数同地域；函数通过**外网地址**访问（函数未绑定 VPC，绑了 VPC 就去不了公网，而千帆必须走公网） |
| 凭据 | `private/nanming-redis.txt`（git 忽略）：外网地址/端口/密码，随 `NANHANG_REDIS_*` 三项进函数配置 |
| 自检 | `node scripts/redis_store_check.mjs`（需要上面三项环境变量），16 项检查含并发竞争 |

几点取舍写在明处：

- **为什么不用 VPC 内网**：函数一旦绑定 VPC，公网出口就要靠 NAT 网关（按小时计费，比 Redis 本身贵得多），
  而千帆必须在公网。用外网地址 + 强密码 + 只跑会话状态，是本项目当前阶段成本与风险的平衡点。
- **外网地址意味着风险**：密码是唯一门槛。已在用的键都有 TTL、前缀 `nm:`，不含成绩；真要收紧时，
  可以改走「函数绑 VPC + NAT 网关」或给 Redis 开 SSL。
- **销毁实例**：控制台销毁后，函数里的 `NANHANG_REDIS_*` 要一并删掉；否则生产档会因为「配了但连不上」
  让 AI 整体不可用（`/readyz` 的 `state_store` 为 false），而不是悄悄退回内存档——这是有意的失败方式。
  2026-09-14 实测补充：把三项删干净而不动别的，生产档会**整个函数拒绝启动**（`productionGuard` 抛
  `refusing to start: production requires a shared state store`），连不依赖 Redis 的 `/v1/school/identify`
  也一起不可用。要让站点继续跑，必须同时设 `NANHANG_AI_ALLOW_MEMORY_STORE=1`（单实例试用档）；
  代码里没有「站点正常但 AI 关闭」这个档位，别指望只删环境变量能关掉 AI。

## 三·五、思考档位：服务端默认最高档，学生可以自己切

北辰把档位固定在云端最高档、页面不带模型字段。南溟沿用「服务端配置」这一点，但**默认档是
`deep`（质量优先，负责人的明确选择）**，同时在界面上给学生一个三选一的开关
（谈心章节 AI 面板的「回答方式」）。学生切档只影响下一轮，已经拿到的回复不作废。

| 档位 | 下发内容 | 界面上叫什么 | 实测（同一句话） |
|---|---|---|---|
| `deep`（默认） | `thinking: enabled` + 预算 4096，上限 8000 | 深（默认） | 17.0 秒 / 9.5 秒 |
| `standard` | 不下发该字段，由端点决定 | 标准 | 24.8 秒 / 19.8 秒（端点默认就是这个档） |
| `speed` | `thinking: disabled`，上限 2000 | 快 | 4.9 秒 |

实测结论：

- **深档确实更慢，慢在出字之前**（模型要想完才开始说），所以等待提示必须一直在；
  服务端在深档下把首字节上限放宽到 120 秒、整轮 300 秒，否则每一轮都会在默认的 30 秒被掐断。
- **思考与正文共用单轮 token 上限**：`max_tokens=300` 且开思考时，300 个 token 全用在思考上、
  正文 0 字。深档因此配 8000 的上限——改档位时不要只改思考预算、忘了上限。
- 三档都实测跑通，格式（正文 + 标记 + JSON）与安全校验在每一档下都成立。

## 三·六、提示词：借北辰的谈话纪律，问南溟自己的问题

北辰的提示词在前端页面里（它的中转函数是纯转发）。我们借的是它的**谈话纪律**，
提问内容则按南溟自己的产品重写——北辰问的是「选文还是选理」，南溟要分辨的是三条专业方向。

**借来的纪律（不照抄内容）**

- 每轮先接住学生刚说的**具体内容**，再往前走一小步；不要「我非常理解你的感受」这类套话，不评判不说教。
- **只问一个问题**，而且问题要能引出一段经历、一个感觉或一次取舍，不是收集抽象性格词。
- **分开记录**：喜欢／擅长／家长期待／担心竞争各自独立，冲突如实保留；只有至少两类线索相互印证才说
  「更偏向」，否则写「仍在观察」。
- **快捷回答只是线索不是结论**；只点选项没有细节时，不当成强证据。
- **反测评腔**：正文与建议理由都不许出现证据编号、「第几问」「判断依据」「证据表明」。
- 对话变长时换切入角度（回到最近一次具体经历、一个还没展开的日常侧面、一句他反复说的话），
  不在原地换词重问。

**按南溟重写的提问内容**

- 明确告诉模型：要分辨的方向只有三个——数据整理与信息核对、结构制作与修改、规则阅读与流程记录，
  提问要能帮学生看出哪条更像他，而不是泛泛聊兴趣。
- 把每条方向**真实配套的那件小任务**写进提示词（整理公开小表格标空值／用纸搭桥记录测试方法／
  读公开规则写出流程），并指示模型聊到某条方向时问学生愿不愿意试、试完什么感觉——
  这是本项目里最有说服力的验证方式，比再问十个问题都管用。
- 要求**问现实条件**（家里怎么想、费用与地域的硬限制、必须照顾的安排），因为它们会进入航线图的现实条件。
- 要求学生已存的原话要先用起来，不重复问已经答过的事。
- 明确划走不属于 AI 的话题：分数、位次、能不能上某所学校由数据库与匹配规则回答；学生问到时把人引到
  「分数轴」和「航线图」，**也不许主动把话题引到具体学校或专业上**（实测中模型这么做过一次，因此写进提示词）。

**实测复验（默认深档）**

- 含糊回答「我也不知道自己喜欢什么，成绩都一般」→ 只问一个问题，且问的是一次具体经历；
  给出 1 条**待确认**方向的建议，行动是「挑一份你熟悉的小数据做一次整理，顺手记下哪一步你最不觉得累」。
- 回答里提到家里希望留在四川、学费有压力 → **0 条建议、0 条行动**：没有硬凑方向，只是接住并继续问。

**没有搬的，以及原因**

- **思考低语**（把模型真实思考的最后一句淡入给学生看）：南溟的规则是思考内容属于草稿、绝不发给学生，
  而且它不过安全扫描——万一模型在思考里写「可以考虑冲一冲」，那句话就到了学生眼前。
  等待体验改用打字指示器解决，不用泄露思考。
- **知识库里的具体数字**（覆盖率 96%、招生计划 28.7 万等）：南溟不许模型自行断言数据，
  事实只能来自发布包。这些数字一旦写进提示词，模型就会当事实说出来。
- **领航／夜航双模式与可点选项**：南溟的问一问面板本来就是自由输入，等同夜航模式；
  引入选项等于新增一套交互与判分口径，不是本轮该做的事。

## 三·七、两种聊法：引航 / 泛舟

参考北辰的领航／夜航（一种给现成答案、一种完全自由），名字按南溟自己的主题起：

- **引航**（默认）——引航员上船带路，每一步都摆出现成答案，点一下就算你答了；
- **泛舟**——取自「泛若不系之舟」（《庄子》，与「南溟」出自同一篇），不设路线、随水而行。

学生在谈心章节的 AI 面板里随时切换，做成两张可以挑的卡（选中那张金铜边框、米色底、衬线名字），
而不是一个小开关：**这是学生自己的选择**。切换下一轮生效，已聊过的内容不受影响。

| | 引航（默认） | 泛舟 |
|---|---|---|
| 问法 | 每轮给 3~4 个可以直接点的答案 | 只问问题，不给选项 |
| 学生怎么答 | 点一个答案，或自己写 | 全部自己写 |
| 服务端 | 提示词要求填 `options`，JSON 里必须给 | 提示词要求 `options` 必须为空数组 |

**它怎么走通的（已实测渲染）**：模式随每一轮请求发给服务端（请求体新增 `mode`，只接受 `guided` / `open`），
提示词按模式要求输出，输出契约里的 `options` 与建议、行动一样要过安全校验
（最多 4 个、每个不超过 24 字、不许出现链接／HTML／录取概率）。

**两道防线保证自由探索不会冒出按钮**：上游在非 `guided` 模式下把 `options` 清空；
前端也只在 `ai.mode === "guided"` 时才渲染选项——两条都有测试盯着。
切走模式会清掉上一轮的选项（它属于上一轮的问法），但已经拿到的回复保留，学生不会丢信息。

**真模型复验（默认深档）**：

- 选择作答：「我不知道自己喜欢什么」→ 返回 4 个可点答案，都是具体的经历或态度
  （「拆装过小物件或做过点手工」「看说明或研究规则时挺专注」「喜欢把乱糟糟的东西排个序」
  「好像真没有，平时都在刷手机」——最后一个就是允许出现的那个「还没想过」）。
- 把第一个答案当作学生的回话再发一轮 → 模型接着问了动手的细节，并**主动给出南溟配套的那件小任务**
  （用纸搭一座小桥、记录怎么测试结实程度），这正是提示词里「每条方向配一件小任务」那一节的落地。
- 自由探索：同样一句话，**0 个选项**。

**等待时间要有心理准备**：默认深档下实测 25~50 秒一轮（深档本来就慢，选择作答还要多想几个答案）。
面板目前只有「等待回复…」，如果试用反馈说等得难受，优先做的是等待提示（北辰那套带秒数与阶段文案的做法），
而不是把默认档调低。

## 四、与北辰的差异（都不是疏漏）

| | 北辰 | 南溟 |
|---|---|---|
| 输出 | 两段式文本，前端按标记分块渲染 | 正文 + 结构化 JSON；**结构化段不下发**，由网关校验后才作为建议卡片 |
| 思考档位 | 固定 `enabled` + `reasoning_effort: max`（云端写死，学生不能改） | 服务端默认 `deep`（最高档），**学生可在界面上自己切三档** |
| 提示词位置 | 前端页面里 | 服务端（`packages/ai-gateway`），前端无法篡改；纪律借鉴自北辰 |
| 超时 | 9 分钟 | 思考档默认 120 秒首字节 / 300 秒整轮；否则 30 / 90 秒，环境变量可覆盖 |
| 鉴权 | TOTP + 会话 | 沿用网关既有会话机制；学生身份是 TASK-13，尚未做 |

南溟的回复要过 `validateCareerTurnOutput`：正文不能出现概率、冲稳保、链接或 HTML；每条方向建议
必须引用**学生自己保存过的原话 ID**。引用不到（编造 ID、或干脆没引用）的那一条建议会被丢掉、
不展示给学生，但**同一轮的正文保留**——正文本身已经过安全扫描、伪造引用也不会渲染，
为 JSON 里的一条建议把学生刚等到的一整段回复换成「未通过安全校验」代价太大。
被丢掉几条、为什么丢，记在 complete 帧的 `dropped_suggestions` 里（学生端不读这个字段），
便于上线期观察模型的引用质量。所以模型侧提示词里同时给了「边界七条 + 输出格式 + 可引用证据 + 可选方向 ID」。

## 五、故障对照

| 现象 | 原因与处置 |
|---|---|
| 启动即退出，提示需要 `QIANFAN_API_KEY` | 显式要求了 `qianfan` 但配置不全；补全或去掉 `NANHANG_AI_UPSTREAM` |
| 启动即退出，提示主机不在允许名单 | `QIANFAN_BASE_URL` 被改成了非官方域名；这是防止密钥外发的保护 |
| 回复被替换成「未通过安全校验」 | 模型输出了概率、冲稳保、链接或 HTML；看 `error` 帧的 detail，按提示词收紧 |
| 每轮都没有方向建议 | 该会话没有已保存的原话（提示词里就会写明「不要给建议」），或模型给的建议没引用注册过的证据 ID 而被丢掉 |
| 正文里出现学生没说过的话 | 检查是不是给真模型配了 `NANHANG_ALLOW_DEMO_EVIDENCE=1`，或前端漏发了证据字段 |
| 学生聊到一半被要求重新兑换访问码 | 会话只存在函数进程内存里：没配 Redis（或 Redis 不可达，`/readyz` 的 `state_store` 会是 false）。检查 `NANHANG_REDIS_HOST/_PORT/_PASSWORD` 三项。**2026-09-14 起线上就是这个状态**（计费冻结，属预期） |
| `/healthz` 里 `store` 是 `memory` | 共享存储没配齐。2026-09-14 起线上为预期状态（Redis 已销毁 + `NANHANG_AI_ALLOW_MEMORY_STORE=1`）；若共享存储已配好却仍显示 `memory`，说明三项没配齐 |
| 函数启动即退出，提示 `refusing to start: production requires a shared state store` | 生产档缺共享存储且没有单实例开关。补 `NANHANG_REDIS_*` 三项，或设 `NANHANG_AI_ALLOW_MEMORY_STORE=1` 跑单实例档；注意此时连学校查询端点也一起不可用 |
| 首字节很慢甚至超时 | 端点默认开着思考档位；先试 `QIANFAN_THINKING=disabled`，或放宽两个超时变量 |
| 正文几乎为空、但确实烧了 token | 思考吃满了单轮上限。实测：`thinking` 开启 + `max_tokens=300` 时，300 个 token 全用在思考上、正文 0 字。把 `QIANFAN_MAX_TOKENS` 调大（4000 起），或设 `QIANFAN_THINKING=disabled` |
| 上游 401/403 | 密钥或模型名与 Token Plan 不匹配；错误消息里只有状态码，不含密钥 |

## 六、历史真实模型验证与当前剩余范围（2026-09-12 核对）

- **已于 2026-09-12 用真实凭据验证通过。** 凭据按交接库自己的规矩从《操作执行清单》附录 A 读取，
  探针脚本放临时目录、用完即删，全程没有打印密钥。结果：
  - 直连探针 HTTP 200，首字节约 1.0 秒，端点与模型名（`qianfan-code-latest`）有效；
  - 完整网关跑一轮：HTTP 200、约 16 秒、143 个 delta 帧、**0 个 error 帧**，552 字正文，
    **未被安全校验降级**；1 条建议同时引用了注册过的两条原话，2 条行动，
    「学生看到的文字」与「校验后的 reply」**逐字相同**；
  - 模型确实在守边界：它主动把「兴趣表达」与「实际经历」分开陈述（`PROMPT_BOUNDARY` 第 2 条）。
- 仍然未验证：多轮连续对话、多人并发、真实学生规模下的限额与计费，
  以及上游不遵守「正文 + 标记 + JSON」格式时的兜底在真实模型上的表现（当前靠提示词约束）。
- **共享存储已接上（2026-09-12）。** 内存档在多实例下不共享会话：SCF 并发上来会起多个实例，
  学生的第二轮请求落到另一个实例就会得到 401，被要求重新兑换访问码。现在函数跑的是
  `RedisStateStore`（`/healthz` 的 `store` 字段为 `redis`），会话、令牌索引、幂等记录与额度都在
  Redis 里，任何实例都能接着服务同一个学生。实现要点：
  - `StateStore` 接口改为异步（网络存储天然异步），`MemoryStateStore` 与 `RedisStateStore`
    实现同一套语义，网关只依赖接口；
  - 每次占位/迁移/撤销都是**一个 Lua 脚本**，判断与写入不分离，所以并发下不会超卖额度、
    不会重复结算；`claim` 并发竞争已实测「三方同时抢同一个 request_id 只有一方成功」；
  - 自带一个极小的 RESP 客户端（`redis-client.ts`），不引入第三方依赖；
  - 键统一前缀 `nm:`，全部带 TTL（默认等于会话 TTL），学生不用了自动过期；
  - 冷连接的超时按 5 秒算（实测首次 DNS 解析加握手可到 0.5 秒，2 秒预算会被 DNS 吃光，
    那会误判成「存储不可用」而把 AI 关掉）。
- **验证方式**：`scripts/redis_store_check.mjs` 对着真实实例跑 16 项检查（含并发竞争与撤销），
  连不上会明确报错；自动测试里另有 13 项线级测试（命令编码、AUTH、断开重连、超时、键名与 TTL）。
  线上另跑过「两个学生同时兑换并各聊一轮」，两轮都是 200。
- 仍然未验证：真实学生规模下的并发与限额、上游不守格式时的兜底表现（当前靠提示词约束）、
  以及学生本人身份（TASK-13）。
- **学生原话链路已在 e2001cb 实现**：前端发送自己保存的原话及最近对话上下文，服务端校验字段、长度、证据类型，幂等哈希包含证据；非空证据同时用于提示词和输出引用校验。新增自动测试已通过，见当前验证结果。
- **空证据回退已在 2026-09-12 隔开**：`demoEvidenceAllowed()`（`apps/api/src/server.ts`）只在假上游（本地联调、验收脚本）
  允许演示原话顶替；接真模型时服务端注册表为空，学生没存过原话就只得到提问、不得到建议。
  起因是线上实测：演示原话被模型当成学生的经历引用，回复里出现「你之前说搭纸桥记测试方法」这种学生没说过的话——
  假记忆比没有建议更伤信任。显式设置 `NANHANG_ALLOW_DEMO_EVIDENCE=1/0` 可覆盖默认判断。
- SCF 宿主、打包/部署脚本和生产 TOTP/CORS 配置已提交；TOTP 后端已上线（函数版本 9），对应前端发布状态见项目进度；TASK-14 进行中。
  学生身份（TASK-13）、真实学生规模的验收与回滚演练仍未完成；共享存储与线上 AI 链路已完成，见上文与实施记录。
- 模型是否严格遵守「正文 + 标记 + JSON」的格式只在提示词层面约束；不遵守时会走兜底
  （末尾 JSON 识别、无建议保留正文），不会把原始 JSON 显示给学生，但建议卡片会为空。


## 五步主界面词表协议（ADR-003，2026-09-12）

主界面只保留引航与泛舟两种 AI 聊法；旧固定问答已退出主入口。请求新增可选 `direction_catalog`（最多 500 项，每项 id/name；id 为规范化名称的 catalog: 前缀键），由当前发布目录的专业类派生，缺类别时使用真实专业名称。该字段参与幂等内容，前后端必须配套发布。

系统提示词只允许目录中的方向 ID，服务端输出校验和主界面再次按目录及本次学生原话过滤。具体专业由发布库展开，学生可以自主选择，交集合并、差集分路；不是由模型写院校名单或资格判断。新流程带目录时空证据不回退到演示原话。正文要求不列具体专业名称，结构化过滤不等于全面验证自然语言事实。

新的浏览器对话检查使用合成响应，实际 AiGateway 的词表传递与过滤另有 5 项测试。既有线上三轮调用只覆盖当时协议，不代表新词表及五步界面已线上验收。新学校姓名接口不使用 AI 访问码，也不把学生姓名或成绩送给模型。
